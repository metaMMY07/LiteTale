# 0.1.24：文库8章节复用与下一章预加载

本轮在 0.1.23 的网页读取优化上继续改善重复等待。参考资料、固定版本及 REA Evidence 见 [参考核对](REFERENCES.md)。未调整全屏转场、原生卷页绘制、字体、图标或账号保存方式。

## 实现

- `ReadResultCache` 合并相同键的在途 Future，成功后才保留结果；TTL、LRU、条数与内容权重同时约束。清空时切换代次，旧 Future 不能写回或删除新任务。
- 文库8详情/目录缓存最多 20 本、估算权重 2 MB、有效期 5 分钟；正文最多 12 章、文本权重 4 MB、有效期 30 分钟。旧兼容封面/详情快照额外限制为 32 项。
- 键包含文库8主机、阅读会话代次、书籍及章节。应用内登录/登出/镜像切换与网页验证页采用会话都会使旧身份失效；确认登录重定向也同步推进代次。普通网络错误不当作登出。
- 分页与滚动阅读均在当前章显示后等待 900 ms，再计划一个下一章。跨卷时跳过空卷。只有已建立的文库8网页会话空闲时才发预取；不启动额外 WebView、不后台打开验证页、不动有效验证码、不重试预取。
- 预取 fetch 预算 3 秒。前台浏览器操作到来或阅读器失效时，在轮询点中止并由 parking 取消 fetch。切入正在预取的同一章时合并请求；该前台阅读也关闭后，不再补发普通 GET。退出阅读、切章、换会话的取消都由有效性回调约束。
- `ReaderPaginationCache` 原有尺寸、字体、字号、正文与会话键继续生效，命中时复用已经测量的分页结果，没有扩大隐藏排版实例数。
- “清除接口缓存”同时清理新增的进程内复用数据。失败/空结果不会成为可反复命中的成功缓存。

## 安装包实测

使用同一 API 35 x86_64 QA AVD，2560×1800；先测已安装的 0.1.23，再以 `adb install -r` 覆盖为 0.1.24。未操作连接的实体平板。公开样本：书籍 `4343`，章节 `177990`、`177991`。

| 场景 | 0.1.23 | 0.1.24 |
|---|---|---|
| 短时间重新打开相同详情 | 再发详情、目录共 2 个 GET | 0 个 GET，目录正常显示 |
| 返回刚读过的章节 177990 | 再发 1 个正文 GET | 0 个 GET，正文正常显示 |
| 切入下一章 177991 | 点击后获取正文 | 阅读 177990 时已预取，点击后复用，不再请求 177991 |
| 未缓存详情/正文 | 正常联网 | 正常联网，所有观察到的响应为 200 |

切入 177991 后观察到的是预取 **177992**，不是再次获取 177991。自动流程检查了实际公开路径与请求次数，不能将缓存命中解释为首次打开也无需网络。旧版重开详情从点击到最后一次 DOM 完成约 1.26 秒，返回正文约 1.32 秒；新版没有相应网络请求。本轮没有把 UI 路由动画、分页或 ADB 探针开销混成“0 毫秒响应”。

公开搜索 `Re` 仍经过原站真实表单，HTTP 200，并显示“志乃与恋”结果。请求发出到 DOM 完成约 3.3 秒，仍受原站脚本影响，未宣称搜索秒开。第一次尝试的 QA 输入未聚焦，没有触发网络请求；改用已有公开搜索历史重新验证，最终报告为 `after-search.json` 与 `search-result.json`。

横屏双页截图由主代理查看，正文、标题及返回后的页面正常，未出现加载覆盖层。截图仅保留于本地 `build/wenku8-reuse/after-reader.png` 与 `after-return-reader.png`。本轮没有重新测定物理设备的卷页帧率，不据模拟器网络结果承诺 120 fps。

## 边界

网页新增缓存为**进程内复用**，退出进程后可能重新联网；原生接口已有的持久章节缓存继续保留。没有移植全书自动下载、其他源的投机预取、DoH 或大并发搜索。下一章预取可能获取一章最终未被用户打开的内容，预算严格为一个相邻章，不遍历整本书。详情与正文的有效期分别为五分钟与三十分钟，缓存过期、账号/主机变化或用户清理后会重新获取。

最终 APK 与 SHA-256 见 [发布记录](../../releases/0.1.24.md)。本轮只做本地交付，未提交/推送代码或发布 GitHub Release；原工作区 `AGENTS.md` 修改保留。
